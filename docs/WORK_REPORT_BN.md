## ২. কাজের সময়রেখা — চার পর্ব

কাজটা একক জিনিস ছিল না, চার ধাপে হয়েছে এবং প্রতিটা ধাপে আগের ধাপের ভুল ধরা পড়েছে।

### পর্ব ১ — ভিত্তি (১৪ কমিট, `23e4049`-এর আগে)

সম্পূর্ণ সিস্টেম দাঁড় করানো: ২৮ রুটের কনসোল, ৩টা ইঞ্জিন (সিমুলেটর, CP-SAT প্ল্যানার, ১০ ধাপের
ওয়ার্কফ্লো), ৩০ টেবিলের স্কিমা, পারমিশন সিস্টেম, অডিট লগ।

তারপর **নিরাপত্তা ও নীরব ভুলের একটা সিরিজ** ঠিক করা হয়েছে, প্রতিটা আলাদা কমিটে — কারণ প্রতিটা আলাদা
ভাবে ভুল উত্তর দিচ্ছিল:

- প্রতিটা authenticated read endpoint-এ পারমিশন গেট (আগে কিছু রুট খোলা ছিল)
- ডিপেন্ডেন্সি রিকভারি এমন outage মুছছিল যা সে ঘটায়নি
- অপ্টিমাইজার ভুল constraint-কে "বাঁধা" বলে দেখাচ্ছিল
- CSV এক্সপোর্টে spreadsheet formula injection (`=`, `+`, `-`, `@`) — Excel-এ খুললে চলত
- ক্যাসকেড গভীরে supplier ফেল করলে আগের সিদ্ধান্ত বদলাত না
- যে workflow ব্যর্থ হয়নি তাকে retry করা যেত
- সবচেয়ে অন্ধকার দুটো ink রঙ WCAG AA বডি-টেক্সট কনট্রাস্টে পৌঁছাত না
- responsive overflow চেক সব authenticated রুট কভার করত না

**এরপর:** ৯৯ টেস্ট, ২৬ স্মোক — সব পাস।

### পর্ব ৩ — ল্যাপটপে চালানো (৩ কমিট, `21072ac`–`f147152`)

লক্ষ্য ছিল: প্রজেক্টটা **নিজের Windows ল্যাপটপে** তোলা। শূন্য থেকে clone করে হুবহু চালিয়ে গাইড লেখা
হয়েছে (`docs/LAPTOP_SETUP_BN.md`, ~৪৩০ লাইন)।

এখানেই আসল বাগগুলো বেরোয়:

- **PowerShell 5.1 `&&` চেনে না** — গাইডের প্রতিটা copy-paste কমান্ড প্রথম শব্দেই ব্যর্থ হচ্ছিল।
  সমাধান: `scripts/dev.ps1`।
- **`DATABASE_URL`-এর relative path** process-এর CWD-র সাপেক্ষে resolve হচ্ছিল, রিপোর নয়। ফলে
  রিপো রুট ছাড়া অন্য জায়গা থেকে চালালে স্টার্টআপই ফেল। সমাধান: `config.py` এখন দুটো প্ল্যাটফর্মের
  নিয়মেই absolutness দেখে, সবসময় absolute + resolved path দেয়। **৭টি টেস্ট**।

### পর্ব ৪ — ল্যাপটপে আসল রান, এবং Next 16 (৫ কমিট, PR #4, PR #5)

আপনার মেশিনে ইনস্টল শেষ হলে দুটো আসল সমস্যা ধরা পড়ে:

1. **`package-lock.json` `next@15.1.3` পিন করে রেখেছিল** → `CVE-2025-66478`, `npm audit` বলছিল
   **৩টা vulnerability (১ critical, ২ high)**। Next **16.4.6** + postcss **8.5.33**-এ তোলা হয় →
   এখন **০**।
2. **`.env.example` ভুল path** — `./data/...` বলত, অথচ built-in default `backend/data/...`। আগে
   `.env` ছাড়া চালিয়ে তারপর `.env` কপি করলে অ্যাপ **নতুন খালি** ডাটাবেজে উঠত — ডেটা "মুছে গেছে"
   মনে হতো। এখন দুটো একই ফাইলে যায়, আর একটা টেস্ট আছে যেটা নিশ্চিত করে উদাহরণ আর ডিফল্ট একই
   ফাইলে পৌঁছায় (পুরনো মানে টেস্ট ফেল করে — যাচাই করা)।

**Next 16 যা ভেঙেছিল, এবং কীভাবে ধরা পড়ল:**

- **`127.0.0.1` থেকে dev asset-এ 403।** Next 16 cross-origin dev asset ব্লক করে; allowlist-এ
  `localhost` আছে, `127.0.0.1` নেই। `dev.ps1`/`dev.sh` `-H 0.0.0.0` bind করে, তাই inherit করার
  মতো hostname নেই — অথচ গাইড `http://127.0.0.1:3000` খুলতে বলে। ফল: পেজ ২০০ ফেরত দিত, রেন্ডার হতো,
  কিন্তু **JS চলত না** → লগইন native GET submit করে `/login?email=...`-এ যেত। **লগইনই অসম্ভব ছিল।**
  আগের সব চেক status code দেখত, তাই কোনোটাই ধরেনি। Playwright জব ধরল (৭১-এর ৭০ ফেল)।
  সমাধান: `allowedDevOrigins`।
- দুটো **অস্পষ্ট টেস্ট assertion** (Next-এর নিজের `role="alert"` announcer, আর dev-tools বাটন
  `.last()`-এ ধরা পড়া) — দুটোই আসল target-এ scope করা হয়েছে।
- একটা **আসল layout বাগ** — `/admin/audit` ১৩৬৬px আর ১০০০px-এ overflow করত (CI-তে আগে থেকেই ফেল
  করছিল)। দুটো কারণ: `PageHeader`-এর টেক্সট কলামে `min-w-0` ছিল না, আর `1fr` গ্রিড ট্র্যাক
  (`minmax(auto,1fr)`) টেবিলের `min-width`-এর নিচে নামতে চাইত না।
- **`seed.ps1` ফাইল ডিলিট করত** → Windows-এ চলতি API ফাইলটা খোলা রাখে, তাই
  `The process cannot access the file`। এটাই স্বাভাবিক সময় (সার্ভার চালু রেখেই রিসেট চায় মানুষ)।
  এখন ফাইল না মুছে **টেবিল খালি করে** আবার সিড করে — API চালু থাকলেও চলে (যাচাই করা)।

**ফল:** E2E জব, যেটা `main`-এ আগে থেকেই লাল ছিল, এখন **৭১/৭১ সবুজ**।

## ৩. যেসব ভুল ধরা পড়েছিল, এবং কেন সেগুলো গুরুত্বপূর্ণ

এই রিপোর সবচেয়ে দরকারি অংশ এটা — কারণ প্রতিটা ভুল **নীরব** ছিল।

| ভুল | উপসর্গ | কেন ধরতে সময় লেগেছিল |
| --- | --- | --- |
| `127.0.0.1`-এ dev asset 403 | পেজ খোলে, বাটনে কাজ করে না | HTTP status ২০০ ছিল — শুধু JS চলত না |
| `.env.example` ভুল path | "ডেটা মুছে গেছে" | পুরনো ফাইল সরে পড়ে থাকত, নতুন খালি ফাইল চলত |
| forwarded path-এ `\U` escape | SyntaxError | traceback-এর ভুল ফ্রেম (টেস্ট ফাইল) দেখাচ্ছিল, আসল কারণ `config.py`-তে |
| `Remove-Item` file lock | reset কখনো চলত না | Linux-এ проблема নেই, শুধু Windows-এ |
| lockfile pin | CVE শিপ করছিল | `package.json`-এ `^15.1.3`, lock-এ `15.1.3` |
| sign-out test | "menuitem not found" | আসলে framework-এর বাটনে click হচ্ছিল |

**শিক্ষা:** status code ২০০ মানে "কাজ করছে" নয়। তাই এখন ব্রাউজার টেস্ট আছে — সেটাই একমাত্র চেক
যেটা hydrate হয়েছে কি না জানে।

## ৫. সীমাবদ্ধতা — স্পষ্ট করে

- **Windows-এর `.ps1` স্ক্রিপ্ট তিনটা** (`dev.ps1`, `seed.ps1`, `smoke.ps1`) লেখার পরিবেশে PowerShell
  নেই, তাই ubuntu-তে চালানো যায়নি। Python-এর অংশগুলো (যেগুলোই আসল কাজ করে) আসল ডাটাবেজে চালিয়ে
  যাচাই করা। বাকিটা আপনার মেশিনে প্রথম রানে যাচাই হয়েছে (`dev.ps1`, `smoke.ps1`) এবং একটা
  (`seed.ps1`-এর ডিলিট সমস্যা) ধরা পড়ে ঠিক করা হয়েছে।
- **ব্রাউজার টেস্ট শুধু CI-তে চলে** — এই sandbox-এ `playwright install` ব্লকড।
- **ডেটা সিন্থেটিক** (কাল্পনিক অরোরা ভেল শহর)। ক্যাসকেড মডেলটা dependency-chain screening,
  power-flow solver নয় — ফল সিদ্ধান্ত-সহায়ক, ভবিষ্যদ্বাণী নয়।
- **PostgreSQL ১৬** CI-তে টেস্ট হয়, কিন্তু ডিফল্ট পথ SQLite।
- `scripts/dev.sh` আর `verify.sh` এখনো POSIX-only (`dev.ps1` Windows-এর পথ)।
